# BRD — Responsive Web Design (RWD)

วันที่จัดทำ: 22 ตุลาคม 2026 · ผลทดสอบล่าสุด: 22 ตุลาคม 2026

## 1. สรุป

ปรับเว็บ GameTop (คำต้องห้าม / One Night Werewolf / OHANA) ให้ใช้งานได้ดีบนทุกขนาดจอตั้งแต่ **320px ถึง 1920px+**
ด้วยโค้ดชุดเดียว (React Native Web) — ผ่านเกณฑ์การยอมรับ PageSpeed และไม่มีหน้าไหนต้องเลื่อนแนวนอน

## 2. ความต้องการเชิงระบบ และสิ่งที่ทำ

| ความต้องการ | สิ่งที่ทำ | ไฟล์หลัก |
|---|---|---|
| **Fluid Grid** 320 → 1920px | Breakpoints: มือถือ < 600, แท็บเล็ต 600–1023, เดสก์ท็อป ≥ 1024 · หน้าแรกแสดงการ์ดเกม 1 / 2 / 3 คอลัมน์ · การ์ดคำในเกมคำต้องห้าม 2 / 3 / 4 คอลัมน์ · ความกว้างเนื้อหาสูงสุด 720px (หน้าเล่นเกม) / 1200px (หน้าแรก) | `src/responsive.ts`, `components/ui.tsx` (Screen) |
| **Navigation สำหรับจอสัมผัส** | แถบบนสุด: มือถือใช้ปุ่ม ☰ (Hamburger) เปิดเมนูด้านข้าง, แท็บเล็ต/เดสก์ท็อปแสดงลิงก์ในแถบ — ซ่อนในห้องเกมให้จอเกมเต็มที่ | `components/AppBar.tsx` |
| **Touch ≥ 44×44px** | ปุ่ม/ช่องกรอก ≥ 48px, ปุ่มเล็ก (pill), ชิปตัวเลือก, ปุ่มไอคอน, ปุ่ม +/− ≥ 44px — ตรวจอัตโนมัติแล้วไม่พบจุดที่เล็กกว่า | ทุก component |
| **Swipe** | ปัดการ์ดไปทางซ้ายในหน้า "🎲 สุ่มคำ" เพื่อสุ่มคำถัดไป (ไม่มีแบนเนอร์/แกลเลอรีในระบบ) | `RandomWordScreen.tsx` |
| **Mobile-first content** | หน้าแรกเริ่มด้วยการ์ดเกม + ปุ่ม "สร้างห้องใหม่" · ห้องรอผู้เล่นย้ายปุ่ม "เริ่มเกม" ขึ้นมาไว้ใต้รายชื่อผู้เล่น ก่อนการตั้งค่า (ทั้ง 3 เกม) | Lobby ของทุกเกม |
| **Dynamic Typography** | หัวข้อ, รหัสห้อง, ตัวจับเวลา, คำบนการ์ด ปรับขนาดตามความกว้างจอ (±12–20%) · คำยาวย่อขนาดอัตโนมัติไม่ล้นการ์ด · ช่องกรอกตัวอักษร ≥ 16px กัน iOS ซูมเอง | `useResponsive().fs` |
| **Flexible media** | QR Code และการ์ดวาดด้วย View ตามขนาด ไม่มีรูป/วิดีโอขนาดตายตัว | – |

## 3. ความต้องการที่ไม่ใช่ฟังก์ชัน

| ข้อ | เกณฑ์ | ผล |
|---|---|---|
| Performance | โหลด ≤ 3 วินาที บนมือถือ 4G | ✅ Lighthouse (จำลองมือถือ + 4G ช้า): FCP 0.6 s, LCP 1.9 s |
| Accessibility | WCAG 2.1 AA | ✅ Lighthouse Accessibility 100 · ปรับสีทั้งหมดให้ contrast ≥ 4.5:1 (ตัวหนังสือบนปุ่ม, สีประจำเกม, สีระดับความยาก, ชิปผู้เล่น ≥ 4.64:1 แม้มี 46 คน) · มี role/label สำหรับ Screen Reader ทุกปุ่ม (รวมปุ่มไอคอน), `lang="th"`, หัวข้อเป็น heading |
| SEO | Mobile-first indexing | ✅ Lighthouse SEO 100 · title, meta description, viewport, robots.txt |
| Compatibility | Chrome, Safari, Firefox, Edge · iPhone, iPad, Galaxy | ⚠️ ทดสอบอัตโนมัติด้วย Edge (Chromium) เท่านั้น — ยังต้องทดสอบจริงบน Safari/iOS และ Firefox |

## 4. เกณฑ์การยอมรับ

| เกณฑ์ | ผล |
|---|---|
| Google Mobile-Friendly Test ไม่มีข้อผิดพลาด | ✅ (เครื่องมือของ Google ถูกยกเลิกแล้ว ใช้ Lighthouse SEO/viewport/tap-target แทน — ผ่านทั้งหมด) |
| รูป/สื่อทั้งหมดไม่ล้นจอ | ✅ ตรวจอัตโนมัติ 7 หน้า × 5 ความกว้าง (320, 375, 768, 1440, 1920) — ไม่มี element ล้นจอ ไม่มีการเลื่อนแนวนอน |
| Core user journey บนมือถือ | ✅ สมัคร → หน้าแรก → สร้างห้อง → ห้องรอ → ระหว่างเล่น (ทั้ง 3 เกม) แสดงผลครบที่ 320px |
| PageSpeed Mobile ≥ 75 / Desktop ≥ 85 | ✅ **Mobile 88 / Desktop 100** |

## 5. ยังไม่ได้ทำ / ข้อสังเกต

- ทดสอบบนอุปกรณ์จริง (iPhone Safari, Galaxy Z Fold แบบพับ) และ Firefox
- Performance มือถือเสียคะแนนจาก Total Blocking Time (~500 ms) เพราะ JavaScript ไฟล์เดียว ~540 KB — ถ้าต้องการ 95+ ควรแยกโหลดแต่ละเกม (code splitting)
- เกมหมาป่าตอนกลางคืนตั้งใจใช้ตัวหนังสือสีเทาเข้มบนพื้นดำ (contrast ~5:1) เพื่อไม่ให้แสงจอรบกวนคนข้างๆ
