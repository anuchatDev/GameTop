# BRD — เว็บเกม "คำต้องห้าม" (MVP Web Edition)

## 1. วัตถุประสงค์โครงการ

- พัฒนาเกม "คำต้องห้าม" ให้อยู่ในรูปแบบ **เว็บแอปพลิเคชัน** ที่เข้าเล่นออนไลน์ได้ทุกที่
- ปล่อยเวอร์ชันแรก (MVP) เพื่อทดสอบระบบและการใช้งานจริง ด้วยสถาปัตยกรรมเรียบง่ายและ deploy ได้เร็ว

## 2. ขอบเขตของระบบ

- **User Management** — สมัครสมาชิกและล็อกอิน
- **Lobby & Room Management** — สร้างห้อง / เข้าร่วมห้องด้วยรหัสห้อง
- **Gameplay Loop** — สุ่มแจกคำ, แสดงคำของเพื่อนร่วมห้อง, กดตกรอบ (Kill), สรุปคะแนน

## 3. ข้อจำกัดทางเทคนิคของเวอร์ชันนี้

| หัวข้อ | รายละเอียด | ผลกระทบ / แนวทางอนาคต |
|---|---|---|
| In-Memory Storage | ข้อมูลห้องเกมอยู่ใน RAM ของ backend, ลบห้องที่ไม่เคลื่อนไหวเกิน 6 ชม. อัตโนมัติ | รีสตาร์ต backend แล้วห้องหาย — ถ้าจะ scale หลายเครื่องต้องย้ายไป Redis / DB |
| HTTP Polling | หน้าเว็บถามสถานะทุก 1.5 วินาที (ยังไม่ใช้ WebSocket) | ลดความซับซ้อน แลกกับ request ที่มากขึ้น |
| No Session Persistence | ไม่เก็บ token ลง LocalStorage / Cookie | ปิดหรือรีเฟรชเบราว์เซอร์ต้องล็อกอินใหม่ |

## 4. ความต้องการเชิงฟังก์ชัน

### 4.1 Login & Authentication
- สมัครสมาชิกด้วย Username + Email + Password
- ล็อกอินด้วย Username หรือ Email
- แสดงคะแนนสะสมรวมและประวัติของผู้ใช้ (เก็บใน Database หลัก แยกจากข้อมูลห้องในหน่วยความจำ)

### 4.2 Room Management
- ผู้ที่ล็อกอินแล้ว **สร้างห้อง** (ได้รหัสห้อง 4-6 หลัก และเป็น Host) หรือ **เข้าร่วมห้อง** ด้วยรหัส
- Lobby แสดงรายชื่อผู้เล่น จำกัด 2-6 คนต่อห้อง

### 4.3 Gameplay Loop
- Host กดเริ่ม → ระบบสุ่มคำจากชุดคำแจกให้ทุกคน
- ผู้เล่นเห็นคำของ **ทุกคนยกเว้นตัวเอง**
- มีปุ่มให้ผู้เล่นกดตกรอบ (Kill) เมื่อมีคนเผลอพูดคำต้องห้าม และเลือกคนที่หลอกล่อ
- นับถอยหลัง 5 นาที (sync ผ่าน polling)
- จบเกม (หมดเวลา หรือเหลือรอดคนสุดท้าย) → คำนวณคะแนน แสดงผู้ชนะ และบันทึกคะแนนลงโปรไฟล์

**กติกาคะแนน:** Kill = +1 ต่อคน · รอดจนหมดเวลา = 0.5 · รอด + ทายคำตัวเองถูก = 1 · พูดคำตัวเอง = ตกรอบ

## 5. การเตรียม Deploy ออนไลน์

| ส่วน | เทคโนโลยี | แพลตฟอร์ม |
|---|---|---|
| Frontend | React Native Web (Expo) — export เป็น static site | Netlify / Vercel |
| Backend | Java 17 + Spring Boot 3 (Docker) | Render / Railway |
| Database | PostgreSQL (ผู้ใช้ + คะแนนสะสม) | Neon / Supabase |
| Config | Environment Variables แยก dev / prod | ดู [DEPLOY.md](DEPLOY.md) |

## 6. สถานะการพัฒนา

| Requirement | สถานะ | หมายเหตุ |
|---|---|---|
| 4.1 สมัคร / ล็อกอิน | ✅ | รหัสผ่านเข้ารหัสด้วย BCrypt, ใช้ JWT (อายุ 72 ชม.) |
| 4.1 คะแนนสะสม + ประวัติ | ✅ | หน้าโปรไฟล์: คะแนนรวม, จำนวนรอบ, จำนวนครั้งที่ชนะ, ประวัติ 20 รอบล่าสุด |
| 4.2 สร้าง / เข้าห้อง, Lobby 2-6 คน | ✅ | รหัสห้อง 4 ตัวอักษร |
| 4.3 แจกคำ / ซ่อนคำตัวเอง / Kill / จับเวลา | ✅ | เซิร์ฟเวอร์ไม่ส่งคำของผู้เล่นให้เจ้าตัวจนจบรอบ |
| 4.3 ผู้ชนะ + บันทึกคะแนนลงโปรไฟล์ | ✅ | ผู้ชนะ = คะแนนรอบสูงสุด (เสมอชนะร่วม) |
| 3. ข้อจำกัด (RAM / polling / ไม่เก็บ session) | ✅ ตามที่กำหนด | ผู้ที่ล็อกอินใหม่แล้วกรอกรหัสห้องเดิมจะได้ที่นั่งเดิม |
| 5. เตรียม deploy | ✅ | Dockerfile, render.yaml, netlify.toml, vercel.json, .env.example |
