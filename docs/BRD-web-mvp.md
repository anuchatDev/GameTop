# BRD — เว็บเกม "คำต้องห้าม" (MVP Web Edition + Admin System)

## 1. วัตถุประสงค์โครงการ

- พัฒนาเว็บแอปพลิเคชันเกม "คำต้องห้าม" เวอร์ชันแรก (MVP) ที่เล่นออนไลน์ได้จริง
- มีระบบสมัครสมาชิกและล็อกอินที่เรียบง่าย เข้าถึงง่ายตามมาตรฐานเว็บทั่วไป
- มีระบบผู้ดูแลระบบ (Admin) เพื่อควบคุมดูแล จัดการผู้ใช้งาน และจัดการคลังคำต้องห้ามในระบบ

## 2. ขอบเขตของระบบ

- **User Management** — สมัครสมาชิกและล็อกอิน
- **Lobby & Room Management** — สร้างห้อง / เข้าร่วมห้องด้วยรหัสห้อง
- **Gameplay Loop** — สุ่มแจกคำ, แสดงคำของเพื่อนร่วมห้อง, กดตกรอบ (Kill), สรุปคะแนน
- **Admin System** — จัดการผู้ใช้ และจัดการคลังคำต้องห้าม

## 3. ข้อจำกัดทางเทคนิคของเวอร์ชันนี้

| หัวข้อ | รายละเอียด | ผลกระทบ / แนวทางอนาคต |
|---|---|---|
| In-Memory Storage | ข้อมูลห้องเกมอยู่ใน RAM ของ backend, ลบห้องที่ไม่เคลื่อนไหวเกิน 6 ชม. อัตโนมัติ | รีสตาร์ต backend แล้วห้องหาย — ถ้าจะ scale หลายเครื่องต้องย้ายไป Redis / DB |
| HTTP Polling | หน้าเว็บถามสถานะทุก 1.5 วินาที (ยังไม่ใช้ WebSocket) | ลดความซับซ้อน แลกกับ request ที่มากขึ้น |
| Session | จำการล็อกอินและห้องล่าสุดใน LocalStorage ของเบราว์เซอร์ | รีเฟรชหน้าแล้วกลับเข้าห้องเดิมได้ (เปลี่ยนจาก MVP แรกเพื่อให้ "เข้าถึงง่ายตามมาตรฐานเว็บทั่วไป") |

## 4. ความต้องการเชิงฟังก์ชัน

### 4.1 Login & Authentication
- สมัครสมาชิกด้วย Username + Email + Password
- ล็อกอินด้วย Username หรือ Email
- แสดงคะแนนสะสมรวมและประวัติของผู้ใช้ (เก็บใน Database หลัก แยกจากข้อมูลห้องในหน่วยความจำ)

### 4.2 Room Management
- ผู้ที่ล็อกอินแล้ว **สร้างห้อง** (ได้รหัสห้อง และเป็น Host) หรือ **เข้าร่วมห้อง** ด้วยรหัส
- Lobby แสดงรายชื่อผู้เล่น ขั้นต่ำ 2 คน **ไม่จำกัดจำนวนสูงสุด** (ตั้งเพดานได้ที่ `game.max-players`)

### 4.3 Gameplay Loop
- Host กดเริ่ม → ระบบสุ่มคำจากคลังคำ (เฉพาะคำที่เปิดใช้งาน) แจกให้ทุกคน
- ผู้เล่นเห็นคำของ **ทุกคนยกเว้นตัวเอง**
- มีปุ่มให้ผู้เล่นกดตกรอบ (Kill) เมื่อมีคนเผลอพูดคำต้องห้าม และเลือกคนที่หลอกล่อ
- นับถอยหลัง 5 นาที (sync ผ่าน polling)
- จบเกม (หมดเวลา หรือเหลือรอดคนสุดท้าย) → คำนวณคะแนน แสดงผู้ชนะ และบันทึกคะแนนลงโปรไฟล์

**กติกาคะแนน:** Kill = +1 ต่อคน · รอดจนหมดเวลา = 0.5 · รอด + ทายคำตัวเองถูก = 1 · พูดคำตัวเอง = ตกรอบ

### 4.4 Admin System
- **สิทธิ์:** ผู้ใช้มี role `PLAYER` หรือ `ADMIN` — Admin คนแรกกำหนดผ่าน env `ADMIN_USERNAMES` ไม่มีใครตั้งตัวเองเป็น Admin ผ่านเว็บได้
- **ภาพรวม:** จำนวนผู้ใช้, จำนวนคำ (เปิดใช้/ทั้งหมด), จำนวนห้องที่เปิดอยู่
- **จัดการผู้ใช้:** ค้นหา, ดูคะแนน/จำนวนรอบ, ระงับ/ยกเลิกระงับบัญชี (มีผลทันที), ตั้ง/ถอดสิทธิ์ Admin
- **จัดการคลังคำ:** ค้นหา, เพิ่ม/แก้/ลบคำ, กำหนดหมวดและแพ็ก (สร้างแพ็กเสริมใหม่ได้), เปิด/ปิดใช้งานคำ
- **กันพลาด:** ระงับหรือลดสิทธิ์ตัวเองไม่ได้, ห้ามคำซ้ำ, ต้องเหลือคำที่เปิดใช้งานอย่างน้อย 6 คำ

## 5. การเตรียม Deploy ออนไลน์

| ส่วน | เทคโนโลยี | แพลตฟอร์ม |
|---|---|---|
| Frontend | React Native Web (Expo) — export เป็น static site | Netlify / Vercel |
| Backend | Java 17 + Spring Boot 3 (Docker) | Render / Railway |
| Database | PostgreSQL (ผู้ใช้, คะแนนสะสม, คลังคำ) | Neon / Supabase |
| Config | Environment Variables แยก dev / prod | ดู [DEPLOY.md](DEPLOY.md) |

## 6. สถานะการพัฒนา

| Requirement | สถานะ | หมายเหตุ |
|---|---|---|
| 4.1 สมัคร / ล็อกอิน | ✅ | BCrypt + JWT (อายุ 72 ชม.), จำการล็อกอินในเบราว์เซอร์ |
| 4.1 คะแนนสะสม + ประวัติ | ✅ | หน้าโปรไฟล์: คะแนนรวม, จำนวนรอบ, ชนะ, ประวัติ 20 รอบล่าสุด |
| 4.2 สร้าง / เข้าห้อง, Lobby 2 คนขึ้นไป (ไม่จำกัด) | ✅ | รีเฟรชหน้าแล้วกลับเข้าห้องเดิมอัตโนมัติ |
| 4.3 แจกคำ / ซ่อนคำตัวเอง / Kill / จับเวลา | ✅ | เซิร์ฟเวอร์ไม่ส่งคำของผู้เล่นให้เจ้าตัวจนจบรอบ |
| 4.3 ผู้ชนะ + บันทึกคะแนนลงโปรไฟล์ | ✅ | ผู้ชนะ = คะแนนรอบสูงสุด (เสมอชนะร่วม) |
| 4.4 Admin: สิทธิ์ / ภาพรวม | ✅ | ตรวจสิทธิ์จากฐานข้อมูลทุก request |
| 4.4 Admin: จัดการผู้ใช้ | ✅ | ระงับแล้ว token เดิมใช้ไม่ได้ทันที |
| 4.4 Admin: จัดการคลังคำ | ✅ | คลังคำย้ายจากไฟล์ JSON มาอยู่ในฐานข้อมูล (นำเข้า 100 คำอัตโนมัติครั้งแรก) |
| 5. เตรียม deploy | ✅ | Dockerfile, render.yaml, netlify.toml, vercel.json, .env.example |
